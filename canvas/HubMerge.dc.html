Release Relay hub · how branches work

Orgs in parallel: Git merges, nothing is overwritten

Each dev org has its own branch

Where a release branch starts

  1. Raise: the branch starts from the dev org's own branch (dev2), not from sit, so Git knows what that org started from.
  2. Merge into sit: Git combines A's and B's changes line by line. Different lines in the same class: both kept.
  3. Same lines changed: a conflict. The hub stops before approval and shows it.
  4. Validation deploys the merged result (what SIT will really get), not only B's copy.
  5. After each SIT deploy: sit merges back into every devN branch. Optional: deploy it to the dev orgs too (back-promote).
