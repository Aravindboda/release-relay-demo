Set up, step by step

About 45 minutes for a hub with 2 orgs
1Git repository
2Hub certificate
3Register orgs
4Pipeline logins
5Route
6Slack
7People
8First release
1

Prepare the Git repository Git admin

  1. Create the repository and a branch per org: dev1, sit, prod (the hub can create missing ones).
  2. Copy the two pipeline files to main (see Repository files).
  3. Create a fine-grained token: Contents, Pull requests and Actions read and write.
  4. In the hub: Named Credential RLY_GitHub with that token.
GitHub → Settings · Salesforce Setup → Named Credentials

Pipeline tab: Git connection shows Connected and lists what it checked.

2

Create the hub certificate Salesforce admin

  1. Setup → Certificate and Key Management → Create Self-Signed: release_relay, exportable key.
  2. Download the certificate (.crt) for step 3; Export to Keystore (.jks) for step 4.
3

Register each org Salesforce admin

  1. In the org: External Client App, JWT bearer flow with the hub .crt, admins pre-authorized, integration user's profile.
  2. In the hub: Remote Site for the org's My Domain.
  3. Pipeline → Register an org: role, My Domain, username, consumer key, branch → Save and test sign-in.
The org: Setup → External Client App Manager · Hub: Release Relay → Pipeline

Register an org: the consumer key is saved encrypted and shown as ••••.

4

Give the pipeline a login per stage Git admin

  1. GitHub → Settings → Environments → one per stage (sit, prod).
  2. Secrets: SF_USERNAME, SF_CLIENT_ID, SF_JKS, SF_JKS_PASSWORD. Variables: SF_INSTANCE_URL, SF_JKS_ALIAS.
  3. Deployment branches: main only.
5

Check the route

Pipeline → Route shows DEV1 → SIT → PROD. Use the arrows to reorder stages; Create missing branches makes any branch Git doesn't have yet.

6

Slack (optional)

  1. Slack app with chat:write; bot token in Named Credential RLY_Slack.
  2. On each org card: channel, Post to Slack, Approve in Slack.
  3. /invite @Release Relay in each channel.
7

Give people access

Developer → RLY_Developer · Approver → RLY_Approver · Admin → RLY_Admin (includes Hotfix).

8

Raise a first release

New Release → pick DEV1 → select a class and its test → Review → Raise. Watch it on the release page.

Select: the bar shows the test rule before you can go on.

branches:  main · dev1 · sit · prod
           feature/rel-xxxxx · hotfix/rel-xxxxx
           release-relay-results  ← step results
File or branchWhat it's for
release-relay.ymlStarts the jobs: raise, scan, validate, merge, deploy. Modes: hub, check, resolve, merge.
release-relay.jsThe steps themselves: convert the hub's zip, open the PR, merge the target, run tests, deploy, update branches.
.relay-inbox/Where the hub commits a release's zip and your conflict choices. The pipeline removes them after use.
release-relay-resultsOne folder per release with scan.json, validate.json, merge.json, deploy.json. The hub reads these.
feature/rel-xxxxxOne branch per release, from the developer org's branch.
