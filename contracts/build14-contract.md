## User story (user's words: "manual merge request, like profile level access … need those also to be tracked … in sequence when we back promote, checked by the deployment team")
Some changes can't be deployed as metadata (profile/permission access, data loads, setup settings, a connected app setting, a scheduled job to start…). A developer adds MANUAL STEPS to a release. They travel with the release through every org on the route (SIT, PROD) and to back-promote orgs, in order. The deployment team checks each step off per org. A deploy into an org doesn't start until that org's "Before deploy" steps are done; "After deploy" steps show as open work after the deploy.

## Data model (backend)
RLY_Manual_Step__c (new object, label "Release Relay Manual Step", name field auto-number MS-{00000}, sharing ControlledByParent if Master-Detail else ReadWrite; prefer Lookup with private inner without sharing access like the rest):
  Release__c        Lookup(RLY_Release__c) required, relationship Manual_Steps  (the release that DEFINED the step)
  Title__c          Text(120) required
  Instructions__c   LongTextArea(32768) — what exactly to do (e.g. "Profile Sales User: Account.Region__c read/edit")
  Category__c       Picklist restricted: Permissions (default) | Data | Setup | Other  (labels: Profile or permission access, Data, Setup configuration, Other)
  Timing__c         Picklist restricted: Before_Deploy | After_Deploy (default After_Deploy) (labels: Before deploy, After deploy)
  Sequence__c       Number(4,0) — order within the release (1, 2, 3…)
  Back_Promote__c   Checkbox default true — also do it in back-promote orgs (e.g. Training)
  Org_Scope__c      Text(255) — blank = every org on the route; otherwise comma-separated org record names it applies to
RLY_Manual_Step_Run__c (new object, auto-number MSR-{00000}): one row per step per org deploy:
  Step__c       Lookup(RLY_Manual_Step__c) required
  Release__c    Lookup(RLY_Release__c) required — the release deploying INTO this org (the original, a Promotion that carries it, or a Back_Promote sync)
  Org__c        Lookup(RLY_Org__c) required
  Status__c     Picklist restricted: To_Do (default) | Done | Not_Needed (labels To do, Done, Not needed)
  Done_By__c    Lookup(User), Done_On__c DateTime, Note__c Text(255)
  Order__c      Number(6,0) — position in the deploy's sequence (carried releases in deploy order, then each step's Sequence__c)
Custom permission RLY_Deploy_Team (label "Release Relay Deployment Team") in a NEW permission set RLY_Deploy_Team (label "Release Relay Deployment Team": read on releases/orgs/steps like RLY_Approver, edit on RLY_Manual_Step_Run__c status fields, tab visibility for Releases/Approvals like RLY_Approver) and also in RLY_Admin. FLS: RLY_Developer create/edit steps (definition fields), read runs; RLY_Approver read; RLY_Admin all; RLY_Deploy_Team read steps, edit runs. package.xml: CustomObject members, CustomPermission, PermissionSet. Keep permission set descriptions ≤ 255 chars.

## Apex API (backend implements exactly; UI calls these)
RlyRaiseService.RaiseRequest: ADD List<StepInput> manualSteps; StepInput { String title; String instructions; String category; String timing; Integer sequence; Boolean backPromote; String orgScope; } (a separate top-level or inner class is fine; name it RlyManualSteps.StepInput if RaiseRequest would exceed PMD field limits). Validation: title required (≤120), category/timing valid values, ≤50 steps.
New class RlyManualSteps (+ controller methods on a new RlyManualStepController, @AuraEnabled):
  getSteps(Id releaseId) → StepBoard { Boolean canEdit /*raiser or admin, until the release is first deployed*/; Boolean canCheck /*RLY_Deploy_Team or admin*/; List<StepRow> steps /*definitions incl. carried ones for promotions*/; List<OrgRuns> orgs /*per org the release deploys into: {Id orgId; String orgName; Integer open; Integer beforeOpen; List<RunRow> runs}*/ }
    StepRow { Id id; String title; String instructions; String category; String timing; Integer sequence; Boolean backPromote; String orgScope; String fromRelease /*REL number that defined it*/; }
    RunRow { Id id; Id stepId; String title; String timing; String category; String status; String doneBy; Datetime doneOn; String note; Integer orderNo; String fromRelease; }
  saveStep(String stepJson) → StepBoard  (add/edit a step on a release that isn't deployed anywhere yet; creates runs for the release's current target if the release is past raise)
  deleteStep(Id stepId) → StepBoard (same rule; wrap test DML deletes in try/catch per the user's rule)
  markRun(String runJson /* {runId, status:'Done'|'Not_Needed'|'To_Do', note} */) → StepBoard — RLY_Deploy_Team or admin only ("Only the deployment team can check off manual steps."). Not_Needed requires a note. When the LAST Before_Deploy run for (release, org) becomes Done/Not_Needed AND the release is approved and waiting for them, start the deploy (dispatch mode 'merge' exactly as approval does today — this is a user click, so the callout is allowed; callouts before DML).
Runs are created (in the same transaction as the record that needs them):
  - when a release is raised into its first stage: runs for its steps whose scope includes that org;
  - when a Promotion is created: runs for every carried release's steps (scope includes the next stop), Order__c = carried releases in Carried_Releases__c order, then Sequence__c;
  - when a Back_Promote release is created: runs for steps with Back_Promote__c = true of every release deployed to the hub since that org's last sync (use the same "behind" set RlyBackPromote uses), in deploy order;
Deploy gate (RlyApprovalService / RlyApprovalRuns where the merge is dispatched): if any Before_Deploy run for (this release, target org) is To_Do → don't dispatch; keep Status 'Ready for approval' with Approved_By set, and Detail.notice "Approved. Deploys when the deployment team finishes 2 manual steps before deploy." (RlyReleasePhase); markRun starts it later. Slack Approve follows the same path.
Detail additions (on the existing DetailLinks parent to stay under PMD TooManyFields): Integer manualOpen; Integer manualBeforeOpen; String manualSummary /* "2 manual steps: 1 before deploy (open), 1 after deploy" */. Row (RowKind parent): Integer manualOpen. RlyPromoteController.Ready: Integer manualSteps. Slack card: line "Manual steps: 1 before deploy, 1 after deploy" and on deploy "Deployed · 1 manual step still open in <org>".
